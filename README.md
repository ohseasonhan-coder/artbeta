# Artfolio Studio

문화예술인이 보유한 자료에 따라 제작 경로를 나누고, 입력 내용과 선택한 디자인으로 편집 가능한 PPTX 프로필을 만드는 Next.js 애플리케이션입니다.

## 구현 기능

- `자료 넣기 → 내용 확인 → PPT 완성` 3단계 간편 제작
- PDF·사진·포스터를 구분하지 않는 통합 업로드와 자동 자산 분류
- 첫 화면 링크 입력칸에서 홈페이지·Instagram·YouTube뿐 아니라 나무위키·OTR·쇼글 원문을 최대 8개까지 한꺼번에 저장하고 소개·경력·공연·수상을 통합 구조화
- 가입이나 빈 양식 작성보다 추출 결과를 먼저 보여주는 확인 중심 흐름
- 현재 자료 완성도와 PPT 품질을 높이는 최소 누락 정보 안내
- 일반 PDF 텍스트 추출과 이미지형 PDF 한글·영문 OCR
- 기존 PPTX의 슬라이드 문구와 원본 미디어를 분리하고 AI가 로고·아이콘·장식을 제외한 프로필용 이미지를 최대 8장 자동 선별
- OpenAI 멀티모달 분석: PDF 원문과 페이지 이미지를 함께 읽어 활동명·분야·소개·연혁·공연·수상·언론·연락처를 구조화
- 날짜별 활동을 최대한 누락 없이 추출하고 근거 페이지와 신뢰도를 표시
- 전체 PDF 페이지는 근거용으로 보존하고 내부 사진·포스터·그래픽은 개별 디자인 자산으로 분리
- 추출된 경력·수상·공연을 `맞아요 / 제외` 카드로 빠르게 검토
- 선택형 질문, 기본 정보, 경력 입력
- 입력한 사실만 사용하는 프로필 문구 생성
- Gemini가 대표사진·공연사진·PDF에서 분리한 이미지를 보고 역할, 페이지 서사, 제목과 레이아웃을 설계하는 AI PPTX 생성
- 전체 후보 중 최대 8장의 핵심 이미지를 골라 표지·소개·강점·경력·대표 장면·연락처까지 모든 페이지에 최소 한 장씩 배치
- PPT 제작 직전에 PDF·PPTX에서 분리한 이미지와 동일 인물·권리 검수를 통과한 웹 사진을 자동 보충하고, 동일 사진은 전체 덱에서 한 번만 사용
- 한국어 문장은 띄어쓰기 경계에서만 줄바꿈하며 모든 텍스트 상자에 글자 수·줄 수·프레임 맞춤을 적용해 슬라이드 밖 이탈을 금지
- 모든 제목과 설명을 제안받는 고객의 관점에서 `선택 이유 → 현장 가치 → 검증 근거 → 섭외 행동`으로 구성
- 대표·공연 사진 업로드와 대용량 이미지가 가능한 IndexedDB 초안 자동 저장
- 장르와 제안 목적을 함께 판별해 자동 추천하는 6종 디자인 시스템과 수동 선택 기능
- 모든 슬라이드의 고객 가치 문구를 실제 공연·수상·언론·주요 경력 근거에 연결하고 근거를 화면과 PPTX에 함께 표시
- 표지·소개·강점·2열 경력·대표 장면·섭외 CTA에 서로 다른 편집형 레이아웃을 적용하고, 사진이 부족해도 큰 빈 상자 대신 완성된 타이포그래피 구성과 작은 사진 가이드를 사용
- 실제 미리보기와 편집 가능한 PPTX 다운로드
- 모바일 반응형 UI
- 상세 정보·사진 위치·외부 기록·디자인은 접힌 `세부 설정`에서 선택적으로 수정
- 완성된 프로필로 팀원을 모집하거나 팀 합류를 제안하는 내부 검색 게시판
- 분야·지역·역할·활동 형태·보상 조건 필터와 모집 중/완료 관리

## 실행

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다. 관리자 화면은 `/admin/design-templates`입니다.

## 사이트 관리자 디자인 편집

`/admin/design-templates`는 데모용 템플릿 목록이 아니라 실제 사이트 설정 편집기입니다. 디자이너가 코드 수정 없이 아래 항목을 바꾸고 데스크톱·모바일 화면을 즉시 확인할 수 있습니다.

- 서비스명·로고 문자·상단 메뉴와 브랜드 색상
- 프로필 첫 화면·업로드·신뢰 안내 문구
- 팀원 게시판 제목·설명·버튼·검색 문구와 예시글 노출
- 콘텐츠 폭·카드 모서리·글자 배율·헤더 스타일
- 프로필 첫 화면 영역 순서와 표시 여부
- 실행 취소·다시 실행·초기화와 브라우저 작업본 저장

브라우저 작업본은 해당 기기에서만 미리보기로 사용됩니다. 전체 사용자에게 같은 설정을 게시하려면 `supabase/team_posts.sql`을 최신 상태로 실행하고 서버 환경변수에 다음 값을 추가합니다.

```env
ADMIN_PASSWORD=관리자만_아는_긴_비밀번호
```

Vercel에서는 기존 Supabase 환경변수와 `ADMIN_PASSWORD`를 Production에 추가한 뒤 재배포합니다. 편집 화면의 `사이트에 게시`에서 이 비밀번호를 입력하면 설정이 `site_settings` 테이블에 저장됩니다. 비밀번호는 GitHub에 커밋하거나 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다.

## AI API 연결

무료 테스트에는 Gemini API를 우선 사용합니다. Gemini 키가 있으면 Gemini로 분석하고, 없거나 호출에 실패하면 OpenAI 키를 대체 경로로 사용합니다. 둘 다 없거나 실패해도 OCR·규칙 기반 분석은 계속 동작합니다.

1. [Google AI Studio](https://aistudio.google.com/apikey)에서 Gemini API 키를 만듭니다.
2. 프로젝트 루트에서 환경 파일을 만듭니다.

```powershell
Copy-Item .env.example .env.local
notepad .env.local
```

3. `.env.local`에 아래 값을 입력합니다. 키에는 절대 `NEXT_PUBLIC_` 접두사를 붙이지 마세요.

```dotenv
GEMINI_API_KEY=발급받은_키
GEMINI_MODEL=gemini-3.6-flash
GEMINI_IMAGE_MODEL=gemini-2.5-flash-image
```

4. 이미 개발 서버가 실행 중이었다면 종료 후 `npm run dev`로 다시 시작합니다.

OpenAI를 유료 대체 경로로 함께 사용하려면 같은 파일에 `OPENAI_API_KEY`와 `OPENAI_MODEL`을 추가할 수 있습니다. 키가 없거나 AI 호출이 실패해도 앱은 OCR과 확장된 규칙 기반 분석으로 계속 동작합니다.

### Vercel 배포 시

Vercel 프로젝트의 **Settings → Environment Variables**에 `GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_IMAGE_MODEL`을 추가한 뒤 다시 배포합니다. 환경변수는 Production, Preview, Development 중 사용할 환경에 각각 적용하세요. 비밀키를 GitHub, 클라이언트 코드, 브라우저 콘솔에 넣으면 안 됩니다.

### AI 분석 흐름

PDF 업로드 후 앱은 먼저 모든 페이지를 렌더링하고 텍스트 레이어가 부족한 페이지에 한글·영문 OCR을 실행합니다. Gemini에는 OCR 요약본만 보내지 않고 원본 PDF 전체를 직접 전달해 텍스트, 이미지, 표와 페이지 배치를 함께 분석하며, 구조화된 결과로 연혁·공연·수상·언론을 분류합니다. 분석 화면에는 실제 사용 중인 AI 제공자와 모델이 표시됩니다. Gemini가 실패하고 OpenAI 키가 있으면 OpenAI로 자동 재시도합니다. AI 결과도 자동 확정하지 않으며 사용자가 수정하거나 제외한 뒤 프로필에 반영할 수 있습니다.

PDF 원문 페이지 전체는 최종 PPT 디자인에 넣지 않습니다. PDF 내부 이미지를 분리한 뒤 Gemini가 `인물·대표사진`, `무대·활동사진`, `포스터·홍보물`, `연혁·수상자료`, `보조 이미지`, `사용 제외`로 자동 분류합니다. 로고·아이콘·장식·문서 전체 캡처·저화질 이미지는 자동 제외하고, 선명한 인물 이미지는 대표사진 후보로 자동 연결합니다. 사진은 비율을 유지해 자연스럽게 크롭하고 포스터·연혁 자료는 잘리지 않게 배치합니다.

기존 PPTX를 올리면 슬라이드 XML에서 활동명·소개·연혁·수상·공연 문구를 읽고, 파일 내부의 원본 사진과 포스터를 직접 분리합니다. Gemini가 슬라이드 문맥과 이미지를 함께 평가해 인물·무대·포스터·연혁 자료로 분류하며, 무료 한도 초과 시에도 크기·비율·슬라이드 문맥 기반 분류로 계속 진행합니다. 사용자는 첫 화면에서 자료를 올리고 활동명만 확인한 뒤 바로 PPT 자동 완성을 실행할 수 있습니다.

디자인 다음 단계에서 Gemini가 업로드된 이미지 썸네일, 사용자가 입력한 정보, 제외하지 않은 PDF 추출 항목과 페이지 OCR 원문을 함께 보고 섭외 담당자를 위한 이야기 흐름을 정합니다. PPT 구성 직전에도 기존 PDF·PPTX에서 분리한 이미지를 다시 수집하고 사진이 부족하면 동일 인물·화질·권리 검수를 통과한 웹 사진을 최대 4장 자동 추가합니다. 수상·공연·언론·주요 경력은 하나의 근거 목록으로 합쳐 중복을 제거하고, 모든 근거가 PPT에 들어갔는지 품질 검사로 확인합니다. 자료가 많으면 선택한 페이지 수보다 자동으로 늘려 한 페이지에 억지로 압축하지 않습니다. 긴 본문과 불릿은 단어를 자르지 않고 띄어쓰기 경계에서 다음 줄이나 슬라이드로 이어지며, 모든 텍스트 상자에는 줄 수 제한과 프레임 맞춤을 중복 적용합니다. 경력은 페이지당 최대 6개와 최소 16pt를 기준으로 배치합니다. 같은 사진은 한 PPT에서 한 번만 사용하고, 사진이 부족하면 반복 대신 필요한 사진의 구체적인 안내를 표시합니다. 제목과 설명은 아티스트의 자기소개가 아니라 제안받는 고객이 선택해야 할 이유와 기대할 현장 가치를 전달합니다. 사진과 분리된 PDF 이미지는 독립 프레임에 배치하고 원문 페이지 자체는 넣지 않습니다. 최종 화면과 다운로드되는 PPTX는 동일한 기획·문구·사진을 사용합니다. AI를 사용할 수 없을 때도 같은 고객 관점 규칙과 텍스트 안전 규칙을 적용한 기본 기획으로 대체합니다.

### 웹에서 아티스트 사진 찾기

대표사진과 아티스트명이 등록되면 디자인 단계에서 이미지 검색이 자동 실행됩니다. API 키 없이 Wikimedia Commons를 실제 검색하며, 네이버·Google·YouTube 키가 있으면 해당 결과를 함께 가져옵니다. Gemini는 생체인증으로 신원을 확정하지 않고 기존 대표사진과 후보의 개인·단체 구성, 비식별 외형 단서, 활동 분야, 의상·악기·작품, 무대 맥락을 비교합니다. 검색 문맥 점수와 시각 일치 점수가 모두 82점 이상이고 충돌·워터마크·권리 위험이 없는 사진만 최대 4장 자동 선택하며, 전체 후보는 일치 근거와 출처를 함께 검토할 수 있습니다.

- 네이버: `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`
- YouTube: `YOUTUBE_API_KEY`

Wikimedia Commons는 별도 키나 비용 없이 기본 사용됩니다. 무료 베타에서는 별도 과금 없이 제공되는 네이버·YouTube API 할당량도 선택적으로 사용할 수 있습니다. Google Custom Search는 신규 무료 연동 대상에서 제외합니다. 로컬에서는 `.env.local`, Vercel에서는 Project Settings → Environment Variables에 사용할 검색원의 키를 추가하고 재배포합니다. 추가 검색원은 필수가 아닙니다.

### 빈 사진 영역 AI 채우기

디자인 단계의 `빈 사진 영역 AI로 채우기`는 사용자가 등록한 대표사진과 확인된 경력·장소만 근거로 최대 3장의 보조 이미지를 생성합니다. 생성물은 실제 현장 사진과 혼동되지 않도록 화면과 PPT에 `AI 연출 이미지`로 표시되고, 근거 경력도 PPT 메모에 기록됩니다. 웹 검색 후보에서 워터마크나 높은 권리 위험이 감지되면 추가 버튼이 비활성화됩니다. 워터마크를 삭제하거나 잘라내는 기능은 제공하지 않습니다.

### 나무위키·OTR·쇼글 활동 기록 검색

프로필 정보 단계에서 `소속·단체명`, `활동 시작 연도`, `대표 경력 한 줄`, `공식 링크`를 선택 입력할 수 있습니다. 활동 분야·지역·대표사진을 포함해 이름 외 식별 단서가 3개 이상이면 검색 정확도를 `보통`, 5개 이상이면 `높음`으로 표시합니다.

첫 화면의 `링크가 있다면 여러 개 붙여넣기`에 홈페이지·Instagram·YouTube와 함께 나무위키·OTR·쇼글의 본인 원문 링크를 한 줄에 하나씩 최대 8개까지 입력할 수 있습니다. YouTube는 PPT의 재생 버튼·바로가기로 저장하고, 외부 프로필 페이지는 동시에 공개 본문을 읽은 뒤 Gemini를 한 번만 호출해 소개·경력·공연·수상을 통합 구조화합니다. 활동명·분야·소속·지역·대표 경력을 함께 전달해 동명이인 기록과 광고·메뉴 문구를 제외하며, 각 원문 출처가 경력과 PPT 근거에 남습니다. 사이트가 자동 읽기를 차단하거나 Gemini 무료 한도가 소진된 경우에도 모든 링크는 보존되고 규칙 기반 기본 추출을 사용합니다.

세부 설정의 `외부 프로필·활동 기록 가져오기`는 자동 분석이 차단된 페이지를 사용자가 직접 확인해 보완하는 대체 경로로 유지됩니다. 나무위키는 참고 자료, OTR·쇼글은 플랫폼 등록 자료로 구분합니다.

## 자산 저장 원칙

대용량 PDF, 사용자 사진, 생성된 PPTX/PDF, 원본 디자인 이미지는 Git에 포함하지 않습니다. 실제 운영에서는 아래 버킷을 분리해 외부 스토리지에 저장합니다.

```text
design-assets/templates/{template_key}/
artist-assets/{user_id}/profile-pdfs|representative-images|performance-images/
profile-exports/{user_id}/{profile_project_id}/pptx|pdf|previews|versions/
```

## 무료 팀 모집 게시판 연결

`/team`은 프로필 초안의 활동명·분야·지역·대표사진·주요 경력을 자동으로 불러와 모집글을 만듭니다. Supabase가 연결되지 않은 로컬·Vercel 환경에서는 브라우저 기기 저장 체험 모드로 작동합니다.

여러 사용자가 같은 게시판을 사용하려면 무료 Supabase 프로젝트의 SQL Editor에서 `supabase/team_posts.sql`을 실행한 뒤 다음 서버 전용 환경변수를 `.env.local`과 Vercel에 추가합니다.

```env
SUPABASE_URL=https://프로젝트ID.supabase.co
SUPABASE_SECRET_KEY=sb_secret_...
```

Secret Key는 브라우저 코드나 `NEXT_PUBLIC_` 환경변수에 넣지 않습니다. 게시글은 앱의 `/api/team-posts` 서버 라우트를 통해서만 저장되며, 작성 시 발급한 수정 토큰은 해당 브라우저에 보관되어 모집 완료 상태를 변경할 때 사용됩니다.

저장소에는 템플릿 레지스트리, 레이아웃 정의, 경로와 manifest만 유지합니다.
